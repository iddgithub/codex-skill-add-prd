# Add PRD To Prototype

在不破坏现有原型交互的前提下，把页面与页面级 PRD 融合成可演示、可评审、可交付开发的同屏说明模式。默认使用简体中文。

## 执行边界

- 用户说“添加prd”时，将本 Skill 视为已明确触发；若目标仓库和页面可从当前上下文确定，直接实施，不重复确认结构。
- 只有无法识别目标页面、仓库或关键业务规则且继续会造成明显偏差时，才提出一个简短问题。
- 修改已有原型，不另做一套静态截图页面；保留搜索、筛选、新增、编辑、上传、下载、弹框、分页和路由跳转等现有交互。
- 默认只修改原型和对应 PRD 文件；除非用户明确要求，否则不发布外网、不改变站点访问权限、不修改无关模块。
- 不把演示 Mock 行为自动写成正式业务事实。缺少依据的规则标注为“待确认”，已确认规则才作为确定性 PRD 表述。

## 先判断工作类型

### 初始化

目标页面尚无同屏 PRD 模式时，创建共享组件、页面级 PRD 数据、编号映射和布局样式。

### 增量更新

页面已有同屏 PRD 模式时，仅更新受影响的 PRD 条目、编号锚点和页面映射。锁定已有视觉样式和未受影响的编号，避免无意义重排。

## 页面呈现模型

### 桌面端

- 使用同一个页面容器：左侧为真实可操作原型，右侧为“本页需求说明”。
- 右侧面板建议宽度 `360–420px`，页面主体占据剩余空间；面板内部独立滚动。
- 面板打开时页面主体自然收缩，不遮挡关键操作；关闭后恢复原页面宽度。
- 复用原型现有字体、颜色、圆角和间距。PRD 面板是说明层，不重新设计业务页面。

### 小屏与窄屏

- 宽度不足时将右侧面板改为 Drawer/覆盖层，避免把原型主体压缩到不可用。
- 保证关闭入口、滚动区域和键盘焦点可用。

### 开关与分享

- 在页面头部提供“查看需求说明 / 收起需求说明”开关。
- 支持通过 URL 参数直接打开说明模式，推荐 `?prd=1`；应按当前路由方案正确读取普通查询参数或 HashRouter 内的查询参数。
- 切换 PRD 面板不得重置页面搜索条件、表单、分页或正在查看的业务数据。

## PRD 信息结构

每一个可独立访问的路由页面都维护自己的页面级 PRD，包括一级列表页、详情页、名单页、编辑页等二级页面。右侧面板固定使用以下四个章节：

1. **页面目的**
   - 使用角色、业务场景、页面要解决的问题、结果价值。
   - 明确页面的数据范围与权限边界。
2. **交互说明**
   - 按用户操作顺序描述入口、按钮、表单、搜索筛选、上传下载、弹框、跳转与反馈。
   - 写清前置条件、成功结果和必要的状态变化。
3. **业务规则**
   - 字段定义、必填性、唯一性、数据归属、状态机、权限、计算口径和跨页面关系。
   - 规则必须与实际页面和已确认业务事实一致。
4. **异常情况**
   - 空数据、校验失败、重复数据、权限不足、文件异常、网络失败、部分成功、不可恢复操作及用户提示。

要求内容专业、可测试、无歧义。避免“合理处理”“正常展示”等无法验收的表述；必要时给出明确条件和结果。

## 编号与双向追踪

- 页面上的需求标记使用连续唯一编号 `1..N`。
- 右侧 PRD 中每个与页面元素相关的条目前展示同一个编号；编号必须一一对应，不得一个编号指向多个无关模块。
- 四个章节标题仅作为分组标题，不占用需求编号，防止编号歧义。
- 同一模块内高度相关的行为可聚合为一个编号，例如整组搜索筛选、整组行内操作或同一上传流程。
- 不要在同一个组件上堆叠多个标记；优先放在模块标题、卡片右上角、表头或操作区附近。
- 已有正式 PRD 文件时，将相同编号回写到对应条目前；新增标记不得删除或弱化原始规则。

## 标记视觉与定位

- 使用与原型主色协调的橙色圆形或圆角编号标记；默认白字、清晰可点击、层级高于业务内容。
- 标记采用绝对定位或独立锚点容器，不改变原组件的尺寸、表格列宽和正常文档流。
- 目标容器存在 `overflow: hidden` 时，将标记挂载到不会被裁切的上层容器，或使用 Portal 与坐标定位。
- 编号在右侧面板中保持相同颜色、字号和形态，使评审者能快速对应。
- 不复制截图中的具体业务字段或数量；视觉语言可复用，业务内容必须来自当前页面。

## 推荐代码组织

优先复用现有技术栈，建立轻量共享层：

```text
feature/
├── PrdGuide.(jsx|tsx)       # 面板、开关、编号标记
├── pagePrd.(js|ts)          # 按路由保存页面级 PRD 与编号映射
└── prd-guide.(css|scss)     # 同屏布局与响应式样式
```

- `pagePrd` 以路由或稳定页面键组织，不把大段 PRD 硬编码进业务组件。
- 业务组件只引用 `PrdBadge`、`PrdGuideTrigger` 和当前页面的 PRD 数据。
- 多个页面共用组件和样式，但每个页面保留独立 PRD 内容与编号范围。
- 若项目已有设计系统、Drawer、Tag、Button 或路由查询参数工具，优先复用，不重复造轮子。

## 实施步骤

1. 阅读目标页面、相邻二级路由、现有 PRD/需求文档和 Mock 数据，列出真实可见功能及已确认规则。
2. 按页面拆分 PRD，再按“页面目的、交互说明、业务规则、异常情况”编写内容。
3. 将可视模块与 PRD 条目聚合映射，生成稳定的唯一编号。
4. 创建或复用共享 PRD 组件，接入面板开关、URL 直开能力和响应式布局。
5. 给目标模块添加非侵入式编号标记；覆盖用户指定的一级和二级页面。
6. 若存在正式 PRD 文件，同步编号与已确认规则；未确认内容保留“待确认”。
7. 运行项目已有的构建检查和与本次文件相关的定向检查。

## 必检项

- 左侧仍是原来的可交互页面，原有按钮和路由没有失效。
- 右侧面板四个章节齐全，内容与当前页面一致。
- 页面编号与右侧条目一一对应，没有重复、跳号或孤立标记。
- 一级页面和用户要求的二级页面都已覆盖，各自展示自己的 PRD。
- 打开或关闭面板不重置业务状态；表格和关键操作不被遮挡。
- 增量更新没有改变未受影响的编号和样式。
- 构建通过；只有用户明确要求“自检排版、浏览器验收、截图对照”时，才额外执行浏览器视觉复核。

## 完成交付

最终回复说明：

- 使用了初始化还是增量更新。
- 覆盖了哪些页面和二级路由。
- 新增、更新、删除了多少个需求编号。
- 修改的主要文件及构建/检查结果。
- PRD 模式的打开方式；若用户要求发布，再提供已验证的演示链接。
